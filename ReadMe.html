Quick start

Use these steps the first time you run MyTaskAssistant.

Extract the ZIP Place all files in a normal folder such as Documents or a team-approved working directory.
Open the application Double-click MyTaskAssistant.html. It should open in your default browser.
Load an existing task file Select Load Tasks, choose your saved task file, and confirm that your projects and tasks appear.
Or begin with a new task list Add projects and tasks, then use Save. Your browser may ask you to choose or approve a JSON file.
Save frequently MyTaskAssistant works locally. Use Save after meaningful changes.
Recommended browser: current Microsoft Edge or Google Chrome on a desktop or laptop.

Interface overview

Left navigation

Switch among All, Active, Completed, and Overdue views. Counts update from the loaded task data.

Top and bottom actions

Load tasks, save, export, manage projects, create weekly timesheets, and add tasks from the top action bar or the mirrored bottom action bar below the grid. Both locations use the same command handlers.

Task grid

Review project, task, status, progress, time, AI hours saved, due dates, completion status, dependencies, notes, and actions. The grid does not show a separate Completed date column. A self-contained green checkmark beside Due indicates a task was completed on or before its due date, or that no due date was set; a sad-face icon indicates a late completion. Hover the icon for completion details. Hours and AI Hours Saved display to one decimal place; use the horizontal scrollbar when the table exceeds the available width.

Tasks, subtasks, and dependencies

Creating a task

Select Add TaskOpen the task editor from the upper-right action bar.
Enter the essentialsProvide a title, project, status, progress, priority, due date, and completion date as needed.
Track workEnter Time Spent, Estimated Effort Without AI, and AI Assistance when applicable.
Add relationshipsChoose a parent task for hierarchy and dependency tasks for sequencing.
SaveSelect Save Task to persist valid changes and keep editing, or Save and Close to persist valid changes and close the dialog.

Hierarchy

A child task belongs beneath a parent task. Use the child-task icon on a row or select a parent in the task editor. Reordering is limited to tasks at the same hierarchy level.

The Priority area identifies hierarchy at a glance: a green leaf marks a childless sub-task, a brown branch marks a parent task with child tasks, and a blue standalone-item icon marks a task with neither a parent nor child tasks. Hover a marker to see its parent-child relationship, including the direct child count or parent task name.

Root-level tasks, including standalone tasks and parent tasks, use a very light cool-blue grid-row background that preserves status-pill contrast, with titles using the same accent blue as the completed-task checkmark. Child tasks retain the standard row treatment, while hierarchy icons and labels remain available independently of color.

Notes

The Notes column previews up to five lines. Hover a note to view its complete text. If more text is available, a bold ...(see more) action appears and opens that task in the editor. In the editor, use Expand Notes to enlarge the Notes field for reading or editing long text; select Collapse Notes to restore the standard size.

The task editor opens on Task Detail, which uses the full-width two-column form. For a saved parent task, select the adjacent Sub-Tasks tab to replace the detail form with full-width rows for direct child tasks. Each row shows the child title, status, and Time Spent; select a row to load that child into the same task editor window.

When editing a child task, select its displayed Parent Task name to load that parent in the same editor window. The adjacent × control remains the separate action for removing the parent relationship.

When editing an existing task, use Clone Task before Save Task to create and open a copy in the same editor. The clone uses the saved task data, so unsaved field changes are not included. In the Sub-Tasks tab, select Add Sub-Task to open a new task with the current task preselected as its parent and its project inherited when assigned.

Below Percentage of AI assistance, the editor groups Parent Task above Dependencies on the left and Due Date above Completed Date on the right. Priority order is directly above Notes. Time Spent and Estimated Effort Without AI are aligned side by side with equal-height controls.

Below Time Spent, Auto-Update Percent Complete is selected whenever a task opens. When selected, changing Time Spent calculates Percent Complete from Time Spent ÷ Estimated Hours when Estimated Hours is greater than zero. Clear it to enter progress manually. This preference is only used while the editor is open and is not saved with the task.

Use Save Task to save Notes or other task-detail changes without closing the editor. Use Save and Close, immediately to the right of Save Task, when the task is ready to close. Matching save controls in the editor header use the same behavior.

Archiving

Use the row Archive action to hide a task from normal task views after confirming Are you sure?. The confirmation identifies the selected task and how many child or descendant task records will be included. Archiving a parent archives all descendants, which keeps the normal task list small as completed task sets are retired together. Archived tasks are retained in the data file but no longer participate in Weekly Timesheet, AI Analysis, Export Active, or normal metrics.

Select the left-panel Archive view to search and filter archived records. In that view, the same row action changes to Unarchive, which restores the task to normal views. Cloning an archived child or adding a child to an archived parent automatically unarchives the parent chain so the active child has visible hierarchy context.

Parent task rollups

When a task has child tasks, its Estimated Hours, Time Spent, and Estimated Effort Without AI are read-only values calculated as the sum of all child and nested-child task values. The parent row uses the calculated Time Spent and AI Hours Saved values.

A parent AI Assistance slider is also read-only. Its value is an Estimated Effort Without AI-weighted average of descendant AI Assistance percentages. Hover over the disabled slider for the formula, included task count, total Estimated Effort Without AI, and calculated percentage.

Parent values use terminal work tasks only, so intermediate parent values are never added again. Parent progress is Estimated Hours-weighted when all terminal tasks have estimates; otherwise it uses a task-count average. Parent status is calculated from terminal statuses and uses a concise summary such as In Progress · 1/3. Hover over it for a plain-language explanation, calculated progress, and status counts. Weekly Timesheet and AI Analysis totals also use terminal work tasks only to prevent double counting.

Dependencies

Dependencies identify tasks that should be completed first. They are informational and help users understand sequencing; they do not automatically prevent completion.

The compact Dep? column displays an embedded dependency icon and count only when dependencies exist. Hover or focus it to see every dependency task, its current status, completion state, unresolved references, and whether the current task is blocked.

Completion

A task is treated as complete when its status is Completed, Closed, or its progress reaches 100%. Closed supports intentionally declined, unnecessary, canceled, or otherwise ended work without presenting it as successfully completed. Completed tasks require Estimated Hours and Time Spent greater than zero. Closed tasks may have zero effort. Before either terminal status is saved, a positive Estimated Effort Without AI value requires an AI Assistance percentage greater than 0%; AI Assistance greater than 0% requires a positive Estimated Effort Without AI value but that estimate may be lower than, equal to, or greater than Time Spent. A parent task cannot enter a terminal status until all child and nested-child tasks are terminal. These rules apply to the checkbox, task-editor actions, and saving a terminal status or 100% progress.

Status and progress stay synchronized: setting progress to 100% defaults Status to Completed only when Closed was not explicitly selected; setting Status to Completed or Closed automatically sets progress to 100%. Completion-date and progress synchronization preserve an explicitly selected Closed status.

The editable Completed date records when work finished or was Closed. A missing date is set to today when a task enters either terminal status, while changing to any non-terminal status clears it and reduces 100% progress to 99% so the task is no longer complete. You can then adjust progress as needed. Entering a completion date that is today or earlier automatically sets Status to Completed and progress to 100%.

A task with progress greater than 0% cannot be saved with Status set to Not Started. Select an active status before recording progress.

Filters, search, and views

Filters work together. The task grid displays only rows matching every active condition.

Search

Searches the task's stored content, including title, notes, status, project identifiers, and other fields.

Project

Shows all projects or only tasks assigned to the selected project.

Status

Filters by All, Active, or a specific stored status.

Due date

Supports Past Due, Due Last Week, Due Yesterday, Today, Tomorrow, This Week, Next Week, and Due Next Month.

Due This Week covers the entire current Sunday-through-Saturday calendar week, including items that became past due earlier in that same week.

The Hide Completed checkbox can be combined with the other filters. The left navigation also provides All, Active, Completed, Overdue, Most Recent, Recently Created, Recently Accessed, and Archive views. Most Recent shows up to 10 tasks with the newest creation dates, ordered newest first after active filters are applied. Recently Created shows tasks created during the rolling previous 24 hours, also newest first. Recently Accessed shows tasks opened in the editor during the rolling previous 24 hours, most recently accessed first. Opening an existing task records its access time and marks the dataset unsaved; older data without access history loads normally. Hover over these views in the app to see their filtering criteria. Archive is the only view where archived records participate in search and filtering.

Due Next Month is available in the Due Date dropdown. It includes tasks due from the first through the final day of the next calendar month; it is not a left-navigation view.
Due Last Week is available in the Due Date dropdown. It includes tasks due in the complete Sunday-through-Saturday calendar week before the current week.
Due Yesterday is available in the Due Date dropdown. It includes tasks due exactly on the preceding local calendar day, including completed tasks, and is distinct from Past Due.

Time Spent and AI Productivity

Time Spent is the single source of truth for actual effort. The older separate Actual Effort field is no longer used.

MyTaskAssistant measures AI productivity—not AI usage. Recording AI Assistance indicates that AI delivered measurable efficiency gains while completing the task. If AI did not reduce the effort required—even if an AI tool was used—the task should be recorded with AI Assistance = 0%.

Effort fields

FieldMeaning
Estimated Effort Without AIEstimate of how long the task would have taken if AI had not been available. Required and greater than zero whenever AI Assistance is greater than 0%; it may be lower than, equal to, or greater than Time Spent.
Time SpentThe actual hours used to complete or advance the task.
AI AssistanceThe estimated percentage of work that AI accelerated or meaningfully improved, from 0% to 100%. Record it only when AI produced measurable productivity gains.

AI Hours Saved calculation

AI Hours Saved = Estimated Effort Without AI - Time Spent
Example: Estimated Effort Without AI of 9.5 hours and Time Spent of 5.5 hours produces an AI Hours Saved value of 4.00 h. AI Hours Saved may be positive, zero, or negative, is calculated automatically, and is never stored in the JSON file.

AI Efficiency

The main statistics area shows AI Efficiency after Overall Progress. It is calculated for qualifying terminal items—Completed or Closed tasks—including archived records: total Estimated Time Saved divided by total Estimated Effort Without AI. Terminal describes workflow state and does not mean deleted. It is not an arithmetic average of task percentages.

Hover or focus the main AI Efficiency statistic to see its overall Productivity Multiplier. AI Analysis reports Estimated Time Saved, Estimated Effort Without AI, AI-Assisted Hours, AI Efficiency, Productivity Multiplier, AI Utilization, and Qualifying Task Count; its downloadable HTML includes a per-task Productivity Multiplier column. Productivity Multiplier compares estimated effort without AI to actual Time Spent. Negative results are valid and indicate that AI-assisted work exceeded the Estimated Effort Without AI for the selected tasks.

Row tooltips

Hover over the Hours value to see the estimated and actual hours. Hover over the AI Hours Saved value for a detailed calculation. When no AI assistance value is captured, the default assumption is 0%.

Opening, saving, and backing up JSON

Load Tasks

Select Load Tasks and choose a MyTaskAssistant data file. The application normalizes supported legacy containers and fields when loading, including top-level task arrays and common older effort, status, progress, due-date, notes, dependency, and parent aliases.

Save

Select Save to write the current projects and tasks back to the opened JSON file. Depending on browser security settings, you may need to grant permission or select a location.

When task changes have not been saved, a red (unsaved) indicator appears beside My Tasks. It is hidden on first load, after loading a file, and after Save completes successfully.

If changes are unsaved, closing or reloading the browser page, or navigating away from it, requests the browser's standard confirmation dialog. The browser controls the dialog wording and you may choose to remain on the page or leave and discard unsaved changes.

There is no remote server or automatic cloud backup. Create regular copies of the JSON file using your organization's approved storage and backup practices.

Suggested backup practice

  • Save after major edits.
  • Keep dated backup copies before importing or restructuring many tasks.
  • Do not edit the JSON manually unless you understand the schema.
  • Test a backup by opening it in MyTaskAssistant.

Weekly Timesheet export

The Weekly Timesheet feature creates a browser-viewable, printable HTML report modeled after a traditional weekly timesheet.

Eligible tasks

A task is included when all of the following are true:

  • Time Spent is greater than zero.
  • The task is a terminal work task with a completion date.
  • The task's completion date falls within the selected Sunday-through-Saturday week.

Create a timesheet

Select Weekly Timesheet Open the large timesheet dialog from the main toolbar.
Choose a date within the target week The application determines the full Sunday-through-Saturday period.
Generate or review the preview Changing the week clears the previous rows and refreshes the selected week.
Adjust daily hours Move or divide hours across the day columns. Task totals, project subtotals, daily totals, task count, and grand total update immediately.
Download HTML The result is a standalone file that can be opened, printed, emailed, or retained with supporting records.

How initial daily allocation works

MyTaskAssistant stores a task's total Time Spent, not a separate time-entry history. For the preview, the total is initially placed on the task's completion-date column. Tasks without a completion date in the selected week are excluded. Review and edit the daily values before downloading.

The preview includes sticky day headers and a sticky Grand Total row to remain readable while scrolling.

AI Analysis

The 🤖 AI Analysis button opens a read-only weekly view that summarizes AI-assisted productivity and the hours saved by using AI.

Eligible tasks

A task is included when all of the following are true:

  • Status is anything except Not Started.
  • The task's due date falls within the selected Sunday-through-Saturday week.
  • Time Spent is greater than zero.
  • AI Assistance is greater than zero.
  • Estimated Effort Without AI has a value.

What it shows

Summary badges report Tasks Using AI, total Time Spent, total Estimated Effort Without AI, total AI Hours Saved, and the average AI Assistance percentage. The table lists each eligible task with its project, Time Spent, AI %, Estimated Effort Without AI, and AI Hours Saved, followed by a grand-total row. AI Hours Saved is calculated as Estimated Effort Without AI minus Time Spent and is never stored in the JSON file.

Download

Select Download HTML to save a standalone report named AI_Analysis_<weekStart>_to_<weekEnd>.html that can be opened, printed, or shared.

Data, privacy, and browser permissions

MyTaskAssistant is a local HTML application. It does not require a backend or database and does not send task data to a remote service as part of its built-in operation.

Where data lives

Projects and tasks live in the JSON file selected or saved by the user.

Browser permissions

The browser may request access to open or write a local file. This is expected for local file handling.

Sensitive information

Avoid putting confidential or regulated information in task titles, notes, or exports unless approved by your organization.

Shared computers

Remove exported files and working JSON files from shared locations when they are no longer needed.

Troubleshooting

The application opens but no tasks appear
Confirm that you selected Open JSON and chose the correct working file. Clear active filters and switch to the All view.
Save does not work
Use a current version of Edge or Chrome. Confirm browser permission prompts. If direct saving is blocked, export or copy the data file to an approved writable folder and reopen it.
A task is missing from Due This Week
Confirm its due date is inside the current Sunday-through-Saturday week and that other filters, such as project, status, navigation view, or Hide Completed, are not excluding it.
The weekly timesheet has no rows
Check that terminal tasks have Time Spent greater than zero and a completion date within the selected week.
Hours are on the wrong day in the timesheet
This can occur because task data stores total Time Spent rather than daily entries. Edit the day cells in the preview before downloading.
AI Hours Saved is blank
A valid Estimated Effort Without AI value is required. Time Spent is used as actual effort. Legacy tasks with no AI tracking data display 0.00 h under the default assumption that AI produced no measurable productivity gain.
The exported HTML looks different when printed
Use the browser print preview, choose landscape orientation when necessary, and reduce margins or scale if the weekly columns do not fit.

JSON reference

This section is for advanced users and maintainers.

A simplified task record resembles the following:

{
  "id": "task-123",
  "title": "Prepare weekly status report",
  "projectId": "project-operations",
  "status": "In Progress",
  "percentComplete": 60,
  "estimatedHours": 8,
  "timeSpent": 2.5,
  "estimatedEffortWithoutAI": 5,
  "aiAssistancePercentage": 50,
  "priorityOrder": 1,
  "dueDate": "2026-07-24",
  "notes": "Compile project updates.",
  "dependsOn": [],
  "parentId": null,
  "createdAt": "2026-07-20T15:00:00.000Z",
  "updatedAt": "2026-07-24T16:30:00.000Z"
}

Important compatibility behavior

  • timeSpent is the current actual-effort field.
  • Legacy hoursSpent or actualEffort values are automatically mapped into timeSpent on import.
  • Legacy percentageOfAIAssistance values are automatically mapped into aiAssistancePercentage on import.
  • Legacy estimatedHumanOnlyEffort or estimatedHumanEffort values are automatically mapped into estimatedEffortWithoutAI on import; only the new name is saved.
  • Missing AI assistance is normalized to 0%.
  • AI Hours Saved is derived at runtime and is not stored as a separate authoritative field.
